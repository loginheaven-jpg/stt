## 0. 공통

```powershell
$env:PYTHONIOENCODING = "utf-8"
```

**반드시 준다.** 없으면 채점기가 cp949에서 `—`(U+2014)를 만나 `UnicodeEncodeError`로 죽는다. 출력을 파이프나 파일로 넘길 때만 나타나므로 대화형으로 돌리면 드러나지 않는다. `stt_bench.py`는 고치지 않았다 — 보완서 §5의 우선순위를 따랐다.

측정 기기가 바뀌면 수치도 바뀐다. 이 기준선은 **CUDA · RTX 3060**에서 잰 것이다. CPU에서 재려면 기준선을 다시 잡아야 한다.

## 1. R1 — 정확도 회귀

음원 `audio/sample3.wav` (26.73초) · 정답지 `sample3.txt`

설정은 `baseline.json`의 `settings.common` + `settings.R1_hotwords`다. 화면에서 다음과 같이 맞춘다.

```
모델 large-v3-turbo · 기기 auto · 정밀도 int8 · 언어 한국어 · 탐색 폭 5 · 무음 500
무음 건너뛰기 ☑ · 인식 실패 시 재시도 ☑ · 말버릇 살리기 ☐ · 이름·용어 교정 ☑
이름·전문용어  이승은, 황미혜, 이대표님
화자 분리 ☑ · 화자 수 2명 · 전환 민감도 민감
저장 형식  정본화 초안 md
```

채점.

```powershell
python stt_bench.py sample3.txt "out_text/sample3_canon.md" --nouns 이승은 황미혜 이대표님 --detail
```

| 지표 | 기준값 | 허용 |
|---|---|---|
| 화자 오귀속률 | **0.00%** | +2%p 이내 |
| 화자정답률 | **43.33%** | −3%p 이내 |
| CER | **12.50%** | +2%p 이내 |
| 간투사 보존율 | **44.44%** | −5%p 이내 |
| 고유명사 재현율 | **66.67%** | 동일하거나 상승 |
| 삽입 어절 | **0** | 동일하거나 감소 |
| 화자 수 | **2** | 정확히 2 |

참고값 — 어절오류 43.33% · 발화 10건 · 어절 26개 · 교정 0건 반영 · 1건 보류.

**3회 반복해 정확도 지표는 편차가 0이었다.** 편차가 있던 것은 소요 시간뿐이다 (16.14 · 18.28 · 18.31초). 허용폭은 CUDA 고정 조건에서의 관찰이므로 안전판으로 남긴다.

R1의 배속은 재지 않는다. 26.7초 음원에서는 모델 적재 시간이 전체를 지배해 성능 지표가 되지 못한다.

### 화자정답률 43.33%를 오해하지 않기

**이 값이 낮은 것은 화자 분리 성능 때문이 아니다.** 화자 오귀속률이 0.00%다 — 정렬된 어절 중 화자를 틀린 것이 하나도 없다.

낮은 이유는 어절 정렬 실패다. 정답지는 `만나뵙게`·`진행하게될`처럼 붙여 쓰고 엔진은 띄어 쓴다. 정렬에 성공한 어절이 13개뿐인데 분모는 정답 어절 30개라 43.33%가 된다.

**회귀 지표로는 그대로 쓴다.** 편차가 0이라 변화를 감지하는 데 아무 문제가 없다. "43%밖에 안 되나"로 읽지 말라는 뜻이다.

## 2. R2 — 구조 회귀

음원 `audio/이승은코치.m4a` (18:14) · 정답지 없음. 설정은 R1과 같고 이름·용어만 늘린다.

```
이름·전문용어  이승은, 황미혜, 이대표님, 스쿼트, 에스컬레이터, 헬스클럽, 대중교통
```

산출된 `out_text/이승은코치_canon.md`에서 센다.

| 지표 | 기준값 | 허용 |
|---|---|---|
| 화자 수 | **2** | 정확히 2 |
| 발화 수 | **143건** | ±5% (136 ~ 150) |
| 어절 총량 | **1358개** | ±2% (1331 ~ 1385) |
| 교정 반영 | **0건** | 동일 |
| 교정 보류 | **1건** | 동일 |
| 종료 시각 | **1087초** | ±3초 |
| 배속 | **22.30×** | −20% 이내 (17.84× 이상) |

세는 법 — 발화 수는 `**[MM:SS] 화자N**` 머리글의 개수, 어절 총량은 본문 줄의 공백 구분 토큰 수, 종료 시각은 마지막 머리글의 시각이다.

**배속은 전사 단계만의 값이다.** 화면에 뜨는 숫자와 같다. 화자 분리를 포함한 실제 소요는 104.4초였다 (전사 49.1초 + 화자 분리 55초). 대기열에서 모델 재적재 회귀를 잡으려면 이 두 숫자를 함께 본다.

## 4. v.8 기준선을 폐기한 이유

첫 측정(v2026-08-13.8)은 `fix_terms()`가 어절을 깨뜨린 채 낸 값이었다.

| 시각 | 원문 어절 | v.8 결과 | v.10 결과 |
|---|---|---|---|
| R1·R2 00:00 | 이승입니다 | 이승은니다 | **이승입니다** (보류) |
| R2 07:42 | 상황이라서 | 상황미혜서 | **상황이라서** |
| R2 12:09 | 사이클을 | 사이승은 | **사이클을** |

v.9가 두 규칙을 넣어 셋 다 막았다. 조각을 어절 머리에서만 찾고, 교정 뒤 남는 꼬리가 조사·어미 목록에 있을 때만 반영한다. 목록에 없으면 **본문을 그대로 두고 대장에만 올린다** — 보류다.

바뀐 수치는 둘이다.

**하나, R1 고유명사 재현율이 100%에서 66.67%로 내려갔다.** 이전의 100%는 `이승은니다`라는 깨진 어절 안에 `이승은`이 들어 있어 집계된 값이다. 지금은 `이승입니다`가 그대로 남아 이름이 본문에 없다. **지표는 내려갔지만 본문은 정확해졌다.** 대장이 보류로 기록하므로 사람이 확인해 고칠 수 있다.

**둘, R2 교정이 3건 반영에서 0건 반영·1건 보류가 됐다.** 이전 3건은 전부 파괴였다.

구조 지표(발화 143 · 어절 1358 · 종료 1087초 · 화자 2)는 변하지 않았다. 교정이 제자리 치환이라 어절 수를 바꾸지 않기 때문이다.
