## 0. 공통

```powershell
$env:PYTHONIOENCODING = "utf-8"
```

**반드시 준다.** 없으면 채점기가 cp949에서 `—`(U+2014)를 만나 `UnicodeEncodeError`로 죽는다. 출력을 파이프나 파일로 넘길 때만 나타나므로 대화형으로 돌리면 드러나지 않는다. `stt_bench.py`는 고치지 않았다 — 보완서 §5의 우선순위를 따랐다.

측정 기기가 바뀌면 수치도 바뀐다. 이 기준선은 **CUDA · RTX 3060**에서 잰 것이다. CPU에서 재려면 기준선을 다시 잡아야 한다.

## 1. R1 — 정확도 회귀

음원 `audio/sample3.wav` (26.73초) · 정답지 `sample3.txt`

설정은 `baseline.json`의 `settings.common` + `settings.R1_hotwords`다. 화면에서 다음과 같이 맞춘다.

```
모델 large-v3-turbo · 기기 auto · 언어 한국어 · 탐색 폭 5 · 무음 500
무음 건너뛰기 ☑ · 인식 실패 시 재시도 ☑ · 말버릇 살리기 ☐ · 이름·용어 교정 ☑
이름·전문용어  이승은, 황미혜, 이대표님
화자 분리 ☑ · 화자 수 2명 · 전환 민감도 민감
저장 형식  정본화 초안 md 하나만 (시각 포함 txt 는 기본으로 켜져 있으므로 끈다)
```

**화자 수를 2명으로 맞춘다.** 기본값은 `자동 추정`이다. 기준선은 2명으로 못 박고 잰 값이라
자동 추정으로 두면 재현되지 않을 수 있다.

**연산 정밀도 칸은 없다.** v2026-08-15.1 에서 `int8` 하나로 고정했다. 기준선은 그 값으로
잰 것이라 달라진 것이 없다. 근거는 [CLAUDE.md](../CLAUDE.md) 의 「고를 수 있는 것과
고정한 것」이다.

채점.

```powershell
python stt_bench.py sample3.txt "out_text/sample3_canon.md" --nouns 이승은 황미혜 이대표님 --detail
```

| 지표 | 기준값 | 허용 |
|---|---|---|
| 화자 오귀속률 | **0.00%** | +2%p 이내 |
| 화자정답률 | **46.67%** | −3%p 이내 |
| CER | **11.46%** | +2%p 이내 |
| 간투사 보존율 | **44.44%** | −5%p 이내 |
| 고유명사 재현율 | **100.00%** | 동일하거나 상승 |
| 삽입 어절 | **0** | 동일하거나 감소 |
| 화자 수 | **2** | 정확히 2 |

참고값 — 어절오류 40.00% · 발화 10건 · 어절 26개 · 교정 1건 반영 · 0건 보류.

**3회 반복해 정확도 지표는 편차가 0이었다.** 편차가 있던 것은 소요 시간뿐이다 (15.69 · 17.59 · 17.87초). 허용폭은 CUDA 고정 조건에서의 관찰이므로 안전판으로 남긴다.

R1의 배속은 재지 않는다. 26.7초 음원에서는 모델 적재 시간이 전체를 지배해 성능 지표가 되지 못한다.

### 화자정답률 46.67%를 오해하지 않기

**이 값이 낮은 것은 화자 분리 성능 때문이 아니다.** 화자 오귀속률이 0.00%다 — 정렬된 어절 중 화자를 틀린 것이 하나도 없다.

낮은 이유는 어절 정렬 실패다. 정답지는 `만나뵙게`·`진행하게될`처럼 붙여 쓰고 엔진은 띄어 쓴다. 정렬에 성공한 어절이 14개뿐인데 분모는 정답 어절 30개라 46.67%가 된다.

**회귀 지표로는 그대로 쓴다.** 편차가 0이라 변화를 감지하는 데 아무 문제가 없다. "46%밖에 안 되나"로 읽지 말라는 뜻이다.

## 2. R2 — 구조 회귀

음원 `audio/이승은코치.m4a` (18:14) · 정답지 없음. 설정은 R1과 같고 이름·용어만 늘린다.

```
이름·전문용어  이승은, 황미혜, 이대표님, 스쿼트, 에스컬레이터, 헬스클럽, 대중교통
```

산출된 `out_text/이승은코치_canon.md`에서 센다.

| 지표 | 기준값 | 허용 |
|---|---|---|
| 화자 수 | **2** | 정확히 2 |
| 발화 수 | **143건** | ±5% (136 ~ 150) |
| 어절 총량 | **1358개** | ±2% (1331 ~ 1385) |
| 교정 반영 | **1건** | 동일 |
| 교정 보류 | **0건** | 동일 |
| 종료 시각 | **1087초** | ±3초 |
| 배속 | **22.73×** | −20% 이내 (18.18× 이상) |

세는 법 — 발화 수는 `**[MM:SS] 화자N**` 머리글의 개수, 어절 총량은 본문 줄의 공백 구분 토큰 수, 종료 시각은 마지막 머리글의 시각이다.

**배속은 전사 단계만의 값이다.** 화면에 뜨는 숫자와 같다. 화자 분리를 포함한 실제 소요는 102.2초였다 (전사 48.2초 + 화자 분리 54초). 대기열에서 모델 재적재 회귀를 잡으려면 이 두 숫자를 함께 본다.

**배속을 잴 때는 GPU 를 혼자 써야 한다.** 같은 PC 에서 받아쓰기가 돌고 있으면 전사가
두 배 가까이 느려진다 — 2026-08-15 에 실제로 겪었다(48초 → 87초). 산출물은 바이트
단위로 같았으므로 **정확도 회귀와 배속 회귀는 따로 읽는다.** 산출물이 같은데 배속만
낮으면 코드가 아니라 기계를 의심한다.

앱이 떠 있으면 모델 캐시가 GPU 메모리를 쥐고 있다. 대기열이 비고 `CACHE_IDLE_SEC`(10분)
가 지나면 스스로 놓는다. `nvidia-smi` 로 확인하고 시작한다.

## 4. 기준선을 두 번 다시 잡은 이유

`fix_terms()`의 규칙이 두 번 뒤집혔다. 세 사례에서 갈렸다.

| 어절 | v.8 (가운데 훑기) | v.10 (머리 먼저) | **v.11 (꼬리 먼저)** |
|---|---|---|---|
| 이승입니다 | 이승은**니**다 ✗ | 이승입니다 (보류) | **이승은입니다** ✓ |
| 상황이라서 | 상황**미혜**서 ✗ | 상황이라서 ✓ | **상황이라서** ✓ |
| 사이클을 | 사이**승은** ✗ | 사이클을 ✓ | **사이클을** ✓ |

**v.8은 어절 가운데를 훑어 셋 다 깨뜨렸다.** `상황이라서`의 `황이라`가 `황미혜`로 잡히는 식이다.

**v.10은 조각을 어절 머리에서만 찾고 꼬리를 검사했다.** 파괴는 막았으나 `이승|입니다`를 찾지 못해 보류로 흘렸다. 본문에 이름이 빠진 채 남았고 고유명사 재현율이 66.67%로 내려갔다.

**v.11은 순서를 뒤집었다. 꼬리를 먼저 정하고 머리를 맞춘다.** `입니다`가 꼬리 목록에 있으니 그 앞이 이름 자리다. 조각 길이를 이름 길이 ±1로 묶던 제약이 사라진다.

```
이승입니다   →  이승 | 입니다      머리 "이승" 을 "이승은" 과 대조 (거리 3)
이승님입니다  →  이승님 | 입니다
상황이라서   →  맞는 꼬리가 없다   →  건드리지 않는다
```

`if t in core` 가드는 반드시 남아야 한다. 없으면 `이승은` → `이승은은`이 된다.

세 지표가 함께 좋아졌다 — CER 12.50 → **11.46%**, 화자정답률 43.33 → **46.67%**, 고유명사 66.67 → **100%**. 본문의 `이승은입니다`가 정답지와 정확히 맞아 정렬 어절이 하나 늘어난 결과다. 구조 지표(발화 143 · 어절 1358 · 종료 1087초 · 화자 2)는 세 판 모두 변하지 않았다.

남는 오탐 하나가 있다. `이승만은` → `이승은은`이다. 지정 용어와 자모 거리가 2인 다른 사람 이름은 걸린다. 모든 이름 교정에 내재한 위험이고 대장에 남으므로 감수한다.

### 규칙을 코드에 박아 뒀다

```powershell
python app.py --selftest
```

16개 사례를 돌린다 — 정상 교정 7 · 파괴 차단 3 · 이미 맞음 4 · 무관 2. **`fix_terms()`를 손대면 이것부터 돌린다.** 규칙이 두 번 뒤집힌 자리라 사례를 남겨두지 않으면 세 번째가 온다.
